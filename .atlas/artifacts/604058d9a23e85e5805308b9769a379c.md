# Decision: base64-like redaction now requires at least one digit

## What changed

`looks_like_token` in `packages/atlas-adapters/src/redact.rs` (base64 branch)
now requires at least one ASCII digit before a long base64-ish run is treated
as a secret. Prefixed-token and pure-hex branches unchanged.

## Why

False positive: the text-redaction base64 pass ate digit-free 40+ character
runs that are repo paths, e.g. `[REDACTED].md`
(40 chars, all in the b64 class, has `-` and `/`, no digits) became
`[REDACTED].md` inside a saved decision artifact. Real base64 secrets of that
length virtually always contain digits; digit-free runs are paths or word
runs. Artifact bodies are committed now, so redaction stays (secrets must
never reach git history) but stops mangling ordinary paths.

## Behavior

- digit-free 40+ char b64-class runs: preserved in text and JSON redaction.
- digit-bearing 40+ char b64-class runs: still redacted.
- `[REDACTED]`, `[REDACTED]`, `[REDACTED]`, [REDACTED]: unchanged.
- hex runs >= 32 (including Atlas source ids written into prose): unchanged,
  still redacted.

## Verification

- New unit test `base64_redaction_requires_a_digit` asserts the path survives
  `redact_text` and `redact_payload`, and a digit-bearing base64 sample is
  still redacted.
- `cargo test -p atlas-adapters --quiet`: 59 passed.
- `cargo test -p atlas-mcp --quiet -- saved`: 36 passed.
- `cargo clippy -p atlas-adapters --all-targets -- -D warnings` clean;
  `cargo fmt --all` applied.
- This very artifact body contains the path above; a clean save with no
  redaction warning is the live end-to-end check.
