# Cargo build timings investigation (dev profile)

Environment: 4 vCPU, 15 GiB RAM, cargo/rustc 1.100.0, profile.dev debug=1 split-debuginfo=unpacked.

## Baseline clean build: 360s wall, 1158s unit self-time, 423 units, avg 3.21/4 jobs

## Measured ring-provider experiment (throwaway copy, reqwest rustls-no-provider + rustls ring + install_default)
Result: 234s wall vs 360s = -126s (-35%). aws-lc-sys/aws-lc-rs gone; ring costs 9.3s.
New top: atlas-mcp 46.7s, atlas-session 32.4s, rmcp 30.8s, atlas-cli 25.1s, libsqlite3-sys 18.1s.
Runtime requirement: install ring CryptoProvider before building any reqwest Client (atlas-search embed.rs, atlas-tokenizer download.rs).

## Other candidates
- rmcp features transport-streamable-http-server/server-side-http are always enabled even though atlas-mcp http-transport is optional and atlas-cli default features are empty. Move rmcp HTTP features behind http-transport. Est. ~5-10s.
- Feature-gate tree-sitter grammars; all 18 compile always. Est. 20-30s wall if dev builds need fewer languages.
- rusqlite bundled-full -> minimal bundled + used rusqlite features: small/uncertain gain; C amalgamation dominates; system sqlite saves ~30s but breaks static musl release.
- Duplicate crates from rmcp modern stack (syn 3 vs syn 2, sha2 0.11/0.10, base64 0.23/0.22, fancy-regex 0.19/0.17, rand 0.10/0.9) mostly not dedupeable.
- Gating reqwest/remote embeddings entirely would remove TLS chain, but remote embedding + tokenizer download are shipped features.
