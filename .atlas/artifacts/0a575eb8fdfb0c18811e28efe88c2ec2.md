# Decision: change traceability is a mandatory capture rule

## What changed

The served core workflow now mandates a traceable record for every upgrade,
dependency bump, feature, or behavior fix. Three surfaces carry the rule:

1. `[REDACTED].md` — new **Change
   traceability** bullet in "Record, save, and feed back in every session":
   every behavior change closes with a committed `decision` (or `handoff`)
   artifact (what changed, why, verification) plus a `memory_store`
   `scope: "project"` pointer row with honest importance, recall tags
   (`upgrade`, `feature`, `fix`), and the artifact `source_id`.
2. `[REDACTED].md` — new
   mandatory capture trigger 13: upgrade/bump/feature/fix completed → decision
   artifact + project memory row, "so any later session can trace back the
   change and its purpose".
3. `[REDACTED].md` — "Keep
   durable memory current" gains the traceable-pair paragraph and an
   `--tag upgrade` CLI example.

## Why

Prior state: purpose records existed only when an agent chose to follow the
generic decision/handoff triggers. Nothing forced upgrades to leave what+why,
`search_decisions` holds context-reuse decisions not upgrade rationale, and
repo files (CHANGELOG/SHIPPED) had no standing agent rule. This rule closes
the gap: "what did we change and why" becomes answerable from committed Atlas
records via `memory_recall` → `read_saved_context`, surviving sessions,
clones, and machines (both families committed: `.atlas/memories/`,
`.atlas/artifacts/`).
