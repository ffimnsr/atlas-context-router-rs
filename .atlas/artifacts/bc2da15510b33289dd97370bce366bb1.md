# CI fix: macOS parser fingerprint tests and refactor_parse_validation fuzz crash

## Failure 1: macOS `atlas-mcp` tests expected `current`/`pass`, got `missing`/`fail`

- Tests: `call_tool_status_reports_parser_fingerprint_state`, `call_tool_doctor_reports_parser_fingerprint_check`.
- Root cause: `ToolFixture::new` passed the raw `tempfile` path to `build_graph` and the MCP server. `build_graph` resolves the repo root through `find_repo_root` (`git rev-parse --show-toplevel`), which is git-canonical. On macOS the tempdir is `/var/folders/...`, whose canonical path is `/private/var/folders/...`, so the build wrote the parser fingerprint under `stable_repo_id(canonical_root)` while status/doctor looked it up under `stable_repo_id(raw_root)`.
- Fix: canonicalize the fixture root with `atlas_repo::canonical_filesystem_path`, matching the existing `setup_mcp_fixture` convention.
- File: `packages/atlas-mcp/src/rmcp_server/tests/mod.rs`.

## Failure 2: fuzz target `refactor_parse_validation` panicked on `Supported(Cpp)` + empty content

- Root cause: after the External Grammar Offload Patch, `ParserRegistry::with_defaults()` only registers in-process parsers (Rust, Go, Python, JS, TS, JSON, TOML, HTML, CSS, Markdown, C). `SupportedPathKind` still covers offloaded grammars (Cpp, Java, C#, PHP, Scala, Ruby, Bash), so the target's `expect("supported refactor validation path should return outcome")` was invalid for those kinds. `validate_file_parse_for_refactor` correctly returns `None` when the default registry does not support the path.
- Fix: derive expectations from `ParserRegistry::with_defaults().supports(path)` instead of assuming every `SupportedPathKind` is registered by the refactor revalidation registry; assert outcome presence matches registry support.
- File: `fuzz/fuzz_targets/refactor_parse_validation.rs`.
- Regression test: `validate_file_parse_for_refactor_skips_offloaded_language_paths` in `packages/atlas-refactor/src/engine.rs`.
- `fuzz/Cargo.lock` refreshed: adds `wait-timeout`, drops stale atlas-parser dev-dependency entries.
