## Predicted

Tool 54/55 are read-only lookups; searching saved context must not create decision-memory records that crowd out real decisions in wake_up recent_decisions.

## Actual

Every search_saved_context query (AND cross_session_search pre-53 runs) persists a decision row 'reuse prior decision during saved-context lookup: <query>' with rationale 'saved-context query matched stored decision memory'. After 3 queries the live session's recent_decisions list (wake_up decision_count 7) is dominated by these self-referential entries, and subsequent ledgers decay real decisions in favor of them (compaction promoted them).

## Correction

Decision memory is written unconditionally by the saved-context search path (packages/atlas-mcp/src/session_tools/saved_context.rs:304) whether or not the caller actually reuses anything, so a read-only lookup mutates the decision ledger and pollutes wake-up recall. Fix: only persist a decision when the caller declares reuse (e.g. on a subsequent get_context/decision-reuse path), or tag these telemetry rows as low-priority events that curation always decays instead of promoting.
