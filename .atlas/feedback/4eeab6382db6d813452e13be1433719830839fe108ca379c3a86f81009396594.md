## Predicted

Test 53.2: bounded paged read resumes at the unreturned bytes (next_chunk_offset semantics must be lossless).

## Actual

max_bytes=100 at chunk_offset=0 returns 100 bytes but still reports returned_chunk_ids=[0,1,2], last_included_chunk=2, and next_chunk_offset=3, with continuation_hint 'read more with chunk_offset=3'. The unreturned remainder of chunks 0-2 (1450-100 bytes) is unreachable: paging to offset 3 returns nothing.

## Correction

max_bytes clipping is byte-based while next_chunk_offset is chunk-index-based in packages/atlas-mcp/src/session_tools/artifact_io.rs, so a clipped read advertises a continuation past chunks whose content was dropped. Fix: do not advance next_chunk_offset past a clipped chunk (return the same index plus a byte_offset cursor), or truncate the returned_chunk_ids/last_included_chunk to chunks fully included. Test 53.2 only asserts next_chunk_offset strictly advances, so the data-loss path is untested.
