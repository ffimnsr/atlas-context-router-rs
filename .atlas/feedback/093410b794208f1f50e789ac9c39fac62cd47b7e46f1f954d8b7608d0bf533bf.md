Second and third compact_session calls against an unchanged ledger return summary.no_op == true and 0 new evictions (AGENTS_MCP_TESTS.md Test 49.2)

## Actual

Repeated compact_session on the live MCP session never returned no_op=true: call 2 (before=49, after=49, removed=1, decayed=1) and call 3 (before=56, after=50, removed=4, merged_groups=3) both reported no_op=false. A scoped compact on an empty session (test_session_compact) did return no_op=true.

## Correction

Test 49.2 idempotency is unobservable through MCP because the session ledger mutates between calls (live event capture adds events, so each compact finds new work). Either document that no_op=true only holds for a truly quiescent ledger, or stop recording compaction events into the same ledger being curated. See packages/atlas-session compaction path and packages/atlas-mcp session tool dispatch.
