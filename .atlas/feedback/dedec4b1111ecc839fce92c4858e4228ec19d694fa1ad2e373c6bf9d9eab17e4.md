## Predicted

Doc parity contract for Tools 49-56: one canonical CLI command per tool emitting the same JSON fields/counts as MCP structuredContent.

## Actual

`atlas session save-artifact|read-artifact|search|stats` all fail with 'unrecognized subcommand'. `session compact` has no --session selector (MCP accepts session_id). `session resume` has no --session and no --no-consume (always marks consumed). `session status --json` data uses nested meta{} + exists + resume_snapshot object and lacks status/summary/resume_snapshot_exists/snapshot_consumed; MCP structuredContent is flat and lacks global_memory. `session compact --json` emits {events_before,events_after,merged,decayed,deduplicated,promoted} vs MCP {before_counts,after_counts,removed_events,promoted_events,merged_groups,decayed_events,deduplicated_events,summary}.

## Correction

Canonical parity commands referenced by doc Tools 52-56 do not exist in packages/atlas-cli/src/commands (no session artifact subcommands) and the implemented session commands serialize their own shapes instead of the shared report structs. Fix: add session save-artifact/read-artifact/search/stats wired to the same session_tools functions (packages/atlas-mcp/src/session_tools/{saved_context,artifact_io}.rs) and route compact/status JSON through the shared structs so data == structuredContent; add --session to compact/resume.
