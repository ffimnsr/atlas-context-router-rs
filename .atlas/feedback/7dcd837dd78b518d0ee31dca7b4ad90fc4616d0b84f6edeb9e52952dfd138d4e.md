## Predicted

Tool 58 parity `atlas memory global --json` and Tool 62 parity `atlas memory decisions 'health' --json` exist and mirror MCP get_global_memory/search_decisions; `atlas memory ops` on an unknown id matches MCP memory_ops found=false semantics

## Actual

atlas memory has no `global` and no `decisions` subcommand: `atlas memory global --json` and `atlas memory decisions health --json` both exit 2 "unrecognized subcommand". Decisions are reachable only as `atlas session decisions health --json` (exit 0). Separately `atlas memory ops mem_001 --json` exits 1 "error: no memory with id mem_001" and its JSON has data.history/count with no found field, while MCP memory_ops returns found=false, op_history:[], warnings:[] and no error.

## Correction

Add MemoryCommand::Global and MemoryCommand::Decisions variants (or change the documented parity commands in AGENTS_MCP_TESTS.md tools 58 and 62 to `atlas session decisions`). Align unknown-memory-id behavior with MCP: emit a found=false payload and exit 0 for `atlas memory ops`, and expose the found field in CLI JSON. Files: packages/atlas-cli/src/cli/subcommands.rs (MemoryCommand enum), packages/atlas-cli/src/commands/ memory handlers, packages/atlas-mcp/src/tools/registry/output_schemas for memory_ops.
