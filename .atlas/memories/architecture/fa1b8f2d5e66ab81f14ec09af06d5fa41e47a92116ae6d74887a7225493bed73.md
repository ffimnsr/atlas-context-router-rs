Direction agreed for continuity storage: markdown files under .atlas become source of truth for durable records (memories, decisions, feedback, memoir, overview, tasks, experience edges, session events/resume, artifacts). SQLite stays only as derived rebuildable index (FTS/trigram/embeddings/counters). worldtree.db untouched. Rationale: sqlite corruption risk + no git versioning. Atomic temp+rename writes plus advisory locks for cross-process writers. .gitignore must unignore .atlas markdown paths. Reference: OpenViking filesystem-paradigm memory engine. Resolved: git tracks only memories/, decisions/, feedback/, memoir/, overview/ under .atlas; sessions/events, tasks, artifacts, experience edges stay local. Global-scope memories stay in workspace .atlas. Events ledger is markdown with batched per-process flushes. Reads never write truth files: last_accessed_at, decay_score, access counts, and experience use_count live in a derived index; overview freshness computed at read, never stored; reads lock-free via rename atomicity; derived index updates incremental by content-hash, artifact index refresh deferred via dirty-set, canonical frontmatter serialization keeps rewrites byte-stable for clean git diffs, in-process frontmatter cache keyed by path+mtime, consolidation writes only the new file; lock files centralize under .atlas/locks and atomic-write temps under .atlas/tmp so committed dirs and git status stay clean; event code fences computed per payload (backtick-run length plus one); index dirty state persisted as per-directory mtime watermarks for crash reconciliation; access rows batch in one transaction per recall. L0/L1/L2 tiers retained like OpenViking: L0 = frontmatter via cache, L1 = body summary sections sliced at heading boundaries, L2 = full body plus links; overview level params (l0/l1/l2) stay public contract; topic-level tiering via consolidation output, not generated abstract files. ISSUES.md carries per-phase edge-case blocks and per-phase acceptance-criteria gates: seeded-corpus byte-stable contracts vs sqlite backend, read-path purity, rebuild parity after db deletion, git-clean end-to-end.
